# sonnet-orchestrator — module contracts (read before implementing anything)

Python 3.10 (venv `~/technocore-env/bin/python`; run tests with `~/technocore-env/bin/python -m pytest`).
Deps available: pydantic v2, typer, rich, pyyaml, pytest. **stdlib sqlite3 only** (no SQLAlchemy/networkx).
Package: `src/sonnet_orchestrator/`. Tests: `tests/unit`, `tests/integration`, `tests/scenarios`, fixtures `tests/fixtures`.

## Contest facts the code must encode
- Poem: 14 lines, exactly 10 CMUdict syllables per line (max over pronunciations), stanzas 4/4/4/2, rhyme ABAB CDCD EFEF GG.
  Canonical text = words space-joined, LF lines, blank line between stanzas, no trailing newline; sha256 over that.
- Word token grammar: `[A-Za-z]+(?:'[A-Za-z]+)*[,.;:!?]?`. Letters of a word must ⊆ letters of contributor DID (whole `did:key:...` string, lowercase).
- No consecutive words from the same contributor. First valid word for the next index from any non-previous member wins; others get `version: stale`.
- Referee receipt (`sonnet.receipt.v1` / `sonnet.receipts.v1`) is the ONLY truth. Accepted prefix immutable, suffix mutable. Roster freeze ≠ text freeze.
- One live roster consent per DID; frame identity = exact members[] order + poem_room + room_generation; "consent: withdraw before changing"; after freeze: "roster: frozen", "roster: member already frozen" (member can't join elsewhere); "roster: incomplete consent" rejects words while a member's consent is missing.
- Team room returns HTTP 403 before roster_ready → fall back to discovery room for text.
- Room posts > 2000 chars are refused → chunk.
- Real timings (nohitori): entry 1 roster_ready→complete 94 min, 125 words; entry 2 freeze→complete 6 h 43 min (403 min), 131 words; alternation between 2 people happened for long stretches.

## Module contracts to implement

### solver/ (agent A)
- `solver/assignment.py`: `assign(words: list[WordEntry], writers: list[WriterProfile], *, settings, lead_did, start_index=0, last_contributor=None, unavailable: set[str]=()) -> AssignmentResult(assignments: list[Assignment], cost, feasible, dead_ends: list[int], explanation: list[str])`.
  DP `dp[pos][last_writer][used_mask]` (mask over writers who have contributed at least once when `every_member_must_contribute`) minimising cost = w_latency·latency + w_reliability·(1-reliability) + w_fragility·(1/keys) + w_health·health_penalty, with lookahead ≥ `settings.solver.minimum_lookahead` (default `lookahead_words`=4) refusing paths that make a later word unspellable by any writer allowed at that turn. No consecutive same writer. `backup` = best alternative writer for that index if any.
- `solver/feasibility.py`: `check(words, writers, *, lead_did, last_contributor=None, start_index=0) -> Feasibility(feasible, first_dead_end, reasons)`; `parity_check(words, active_writers, lead_did, start_index, last_contributor)` (two-person alternation: lead-only words must land on lead's turns); `failure_tolerance(words, writers, ...) -> dict[did, Feasibility]` (remove each writer in turn; also "single-failure survivability" KPI = fraction of writers whose loss keeps the plan feasible).
- `solver/reliability.py`: `score(writer: WriterProfile, settings) -> float` (weights from settings.reliability; counts from accepted words / signs, never from "yes"; mass_application penalty = seat_no_sign_weight·seat_no_sign_count + consent_conflict_weight·consent_conflict_count normalised).
- `solver/roster.py`: `optimize(candidates: list[WriterProfile], lead: WriterProfile, settings, size=None) -> list[RosterOption(members, score, coverage: CoverageReport, tolerance, explanation)]` — maximise reliability + lexical coverage + redundant coverage (letters covered ≥2 excluding lead ≥ target) + response speed + historical completion − size penalty; prefer candidates with accepted-word history when `require_accepted_word_history`.
- `solver/explain.py`: `explain_assignment(result, words, writers) -> str` human-readable reasons per index (why this writer, keys count, backup).
- Unit tests in `tests/unit/test_solver_*.py` (small hand-built writers with synthetic DIDs; include a 2-person parity case and a lead-only word dead-end case).

### planner/ + creative/ (agent B)
- `planner/meter.py`: `stress_distance(words, lexicon) -> float` (distance to 0101010101 using best pronunciation, monosyllables/secondary stress wildcard), `line_syllables`, `line_ok(words, lexicon, form)`.
- `planner/validator.py`: `validate_poem_lines(lines, lexicon, form) -> ValidationReport(ok, errors, per_line_syllables, rhyme_pairs_ok, families_distinct)`; final check always calls `lexicon.validate_poem(canonical_text, exact_ten=True)` (official).
- `creative/heuristic.py`: `HeuristicCreativeEngine(lexicon, seed=)` implementing `CreativeEngine` with template-based line generation from letter-constrained word pools (subject/verb/object slots, function words); must produce exactly-10-syllable lines whose words are spellable by the union of allowed letters, prefer words spellable by ≥2 writers (two-key rule).
- `planner/beam.py`: `plan_poem(engine, lexicon, writers, settings, *, accepted_prefix: list[str]=(), theme="", seed=) -> Plan` beam search line by line (width `settings.planner.beam_width`), scoring = meter + rhyme validity + key redundancy + solver feasibility (call `solver.feasibility.check`) ; the accepted prefix is fixed verbatim and only the suffix is generated; result must pass `planner/validator`.
- `planner/replanner.py`: `replan(plan: Plan, poem: PoemState, writers, ...) -> Plan` — keeps accepted prefix immutable, regenerates from `poem.next_index` (or from the first word whose assignment became infeasible), bumps version, `source="solver"`; `reconcile(plan, poem) -> ReconcileResult(prefix_matches, divergence_index)`; hybrid text (accepted words differ from plan) is normal: adopt accepted text, regenerate suffix.
- `planner/landing.py`: `landing_routes(plan, poem, writers, settings) -> list[LandingRoute(final_contributor, path, can_publish)]` — choose who posts the final word given publication capability (writers with `x_account`) and the alternation rule; produce ≥ `settings.planner.landing_routes` routes.
- Unit tests `tests/unit/test_planner_*.py`, `tests/unit/test_creative_*.py` using the real dictionary at `data/cmudict/cmudict.dict` (load once per session via fixture).

### orchestration/ + adapters/mock (agent C)
- `orchestration/state_machine.py`: `GameStateMachine` with explicit transitions (DISCOVER→APPLY→SEATED→ROSTER_PENDING→ROSTER_READY→WRITING⇄RECOVERING→LANDING→COMPLETE→PUBLISH_PENDING→SUBMITTED→ACCEPTED, ABANDONED from anywhere pre-COMPLETE); illegal transitions raise.
- `orchestration/consent.py`: consent state machine per member (NONE→APPLIED→SEATED→SIGNED / CONFLICTED / WITHDRAWN / FROZEN), frame lifecycle DRAFT→SIGNING→READY→FROZEN, SUPERSEDED; waitlist while SIGNING (never seat into a frame that is out for signature); on a new identical frame carry over signatures; signers of the previous frame get REMINDER not DROP; timeout `consent.signature_timeout_s`, reminder every `reminder_interval_s`; "withdraw before changing" ordering; tri-state `AvailabilityState` per other DID with `referee_lag_unknown_after_s`; offer filters: dedupe by (sender, game_id), drop self-offers, drop stale offers (game already frozen/completed), personal offers (`to_did == self`) ranked first.
- `orchestration/health.py`: `HealthManager(settings, clock)`: `expected_ms(did)` from median latencies (floor `minimum_timeout_ms`), classify HEALTHY/SLOW/SUSPECT/DOWN by multipliers, SILENT when seated/signed but no accepted word or post for `silent_after_ms`, recovery on new activity to `recover_to` then HEALTHY after next accepted word. `snapshot() -> list[HealthSnapshot]`.
- `orchestration/dispatcher.py`: `Dispatcher(referee: RefereeAdapter, store, clock)`: `propose(index, text, contributor, base_version) -> Proposal` with unique `request_id = f"w{index}-{hash8}-{did[-6:]}-{ms}"`; `process_receipts()` matches by request_id (late/duplicate receipts idempotent); on ACCEPTED → `store.append_accepted` ; on `version: stale` → mark STALE and re-read accepted state; unknown request_id receipts logged not applied; timeouts → TIMED_OUT.
- `orchestration/table.py`: `render_table(plan, poem, writers, settings) -> list[str]` execution table chunks each ≤ `room.post_char_limit`, header `PLAN v{version} {hash_prefix} next={next_index}`, rows `idx word primary/backup`, chunk `k/n`; `parse_table(text) -> TableHeader` for reading other people's tables; single-owner rule (`plan.owner`), team-scoped state.
- `orchestration/cover.py`: `should_cover(plan, poem, health, settings, now) -> CoverDecision(cover: bool, who, reason)` — cover an overdue word after `expected_ms` of the assignee, only if lookahead (≥2 words) stays feasible for active (non-SILENT/DOWN) writers; hand-off next slot to an active member; encode the 58→59 and 96→97 "beg" traps from nohitori-2 (never cover if the following word is spellable only by us).
- `orchestration/operator.py`: `OperatorBoundary(settings, store)`: `classify(action) -> Decision` from `settings.operator`; `request(action, detail)` records and returns whether allowed to proceed autonomously.
- `orchestration/controller.py`: `Controller(settings, store, lexicon, adapters, engine, clock)` running the final control loop on `tick()` every `scheduler.tick_seconds`: read receipts → reconcile prefix → health → cover/hand-off → replan if needed → repost table if plan version changed → landing → complete → publish/submit handling. Deterministic given adapters + clock. Exposes `snapshot() -> dict` for dashboard/simulation.
- `adapters/mock/`: `FakeClock`, `MockReferee` (rules: contiguous index, no consecutive contributor, DID letters, lexicon membership, version match else `version: stale`; configurable per-writer `delay_ms`, `drop_prob`, `down_after`, `race` (two proposals same index), `delayed_receipt`, `rejected` reasons, `pre_roster_403`), `MockDiscovery`, `MockTeamRoom` (2000-char refusal), `MockPublication`, `ScriptedWriters` (simulated other members proposing their assigned words with latency/health profiles).
- Unit tests `tests/unit/test_orchestration_*.py` + `tests/integration/test_mock_game.py` (4 writers A–D complete a poem end-to-end via Controller with mocks; then the same with C going DOWN mid-poem: accepted prefix unchanged, plan version bumped, poem still completes).

### diagnostics/ + fixtures replay (agent D)
- `diagnostics/replay.py`: parse fixture exports → `ReplayLog(posts: list[RoomPost], words, receipts: list[Receipt], accepted: list[AcceptedWord], members, timeline)`; `accepted_from_export(path) -> list[AcceptedWord]` must reproduce `final_poem.txt` canonical text + sha for both `nohitori` and `nohitori-2` (words joined by lines using 10-syllable boundaries from the lexicon).
- `diagnostics/metrics.py`: from replay → per-writer `WriterProfile` metrics (accepted/rejected counts, word latency median = time from previous accepted word to this writer's accepted word when it was their turn, sign latency median, seat_no_sign, consent conflicts, published entries), KPIs (words/h, time to complete, single-failure survivability from solver).
- `diagnostics/scenarios.py`: named scenario builders (writers + fault injection configs) for Cases A–F and the addendum list: `nohitori-entry1-94min`, `nohitori-entry2-6h43m`, `consent-lag`, `frame-churn`, `mass-applicant`, `self-offer`, `stale-offer`, `dual-table`, `silent-writer`, `58-59-cover-trap`, `96-97-beg-trap`, `hybrid-plan`, `pre-roster-403`, `2000-char-table`, `team-plan-leak`. Store JSON fixtures in `tests/fixtures/scenarios/*.json`.
- `diagnostics/dashboard.py`: `render(snapshot: dict) -> rich.console.RenderableType` (state, members with health/keys/latency, accepted prefix, next word + primary/backup, plan version/hash, pending proposals, landing route, operator approvals pending).
- `tests/scenarios/test_regression_cases.py`: Cases A–F + addendum scenarios (may be marked skip until Controller lands; write against the contracts above).
